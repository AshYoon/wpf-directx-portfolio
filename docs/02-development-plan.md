# 개발 계획서

기준일: 2026-09-05. 1인 개발, 주당 10~15시간을 가정한 **6~8주 초안**입니다. 약 60~120시간의 계획 범위이며, 1주차에 렌더러·빌드 난이도를 확인한 뒤 다시 산정합니다. 일정은 착수 시점 기준이고 확정 납기는 아닙니다.

## 목표와 완료 정의

외부 DB나 원본 에셋 없이 실행되는 WPF + Direct3D 11 장면 편집기를 완성합니다. 사용자가 도형을 배치·선택·편집하고, 저장 후 다시 열어 상태를 복원하는 과정을 2~3분 데모로 보여 줍니다.

최종 완료 조건은 기능 동작, 새 환경의 빌드·실행, 자동·수동 검증 기록, README와 배포물입니다. 문서상의 체크는 실제 확인한 작업에만 적용합니다.

## 검증 계획

| 영역 | 방법 | 성공 기준 |
| --- | --- | --- |
| 장면 모델 | Core 단위 테스트 | ID·Transform 검증과 편집 원복 |
| 저장소 | 임시 디렉터리의 실제 파일 테스트 | round-trip, 버전·파손·저장 실패 처리 |
| MVVM 명령 | 가짜 IRenderer·IScenarioStore 주입 | 실패 응답·취소 시 잘못된 상태 전이 없음 |
| 네이티브 경계 | 작은 연동 실행과 공개 함수 계약 확인 | x64 ABI, 문자열·구조체, 콜백 수명 일치 |
| 화면 | Windows 수동 시나리오 | 조작·표시·포커스와 DPI 정상 |
| 성능 | Release, 고정 장면·카메라·시간 | 평균/p95 프레임 시간 및 메모리 기록 |

CI는 앱·테스트가 생기는 M1에 추가합니다. GPU 화면 검증은 CI의 빌드 성공만으로 대체하지 않습니다. 가능한 경우 WARP 기반 최소 초기화 검증을 별도 구성하고, 실제 GPU 결과는 수동 검증에 기록합니다.

### 필수 수동 시나리오

- 100%·150% DPI에서 배치, 선택, 속성 편집 및 팝업 표시
- 뷰포트 크기 변경·최소화·복원 20회와 입력 재개
- 장면 열기·닫기 30회에서 종료 실패와 지속적인 메모리 증가 확인
- 도형 1/100/1,000개를 같은 조건에서 측정
- 드래그 중 취소, 삭제된 객체의 선택 이벤트, 빠른 연속 입력
- DLL 또는 샘플 파일 누락 시 오류 안내
- 잘못된 JSON·미지원 버전·쓰기 불가 경로에서 데이터 보존
- 새 경로에 받은 배포본에서 시작 → 편집 → 저장 → 재시작 → 복원

### 측정 기록 형식

`커밋 / 날짜 / Windows / CPU / GPU·드라이버 / RAM / 해상도·DPI / 빌드 구성 / 객체 수 / 워밍업·측정 시간 / 도구 / 결과`

60 FPS 등은 목표이며 달성 여부는 실측 후 기록합니다. 통과 기준에 미달하면 숨기지 않고 원인과 지원 가능한 조건을 설명합니다.

## 작업 운영

1. 위 표의 작업 ID를 이슈 제목에 붙이고 완료 기준을 복사합니다.
2. `feat/`, `fix/`, `docs/` 브랜치 하나에서 한 작업을 끝냅니다.
3. 의미 있는 단위로 커밋하고 PR에 동작 변화와 검증 결과를 적습니다.
4. UI 변경에는 화면을, 경계 변경에는 계약과 실패 경로를 첨부합니다.
5. main에 합친 뒤 문서의 진행 상태를 갱신합니다.

1인 저장소에서는 본인 승인이 필수가 되는 규칙을 설정하지 않습니다. PR은 변경 기록과 자체 검토에 활용합니다. 실제 GitHub 이슈·마일스톤 생성은 아직 수행하지 않았으며 이 문서를 초기 백로그로 사용합니다.

## 범위 조정 기준

| 불확실성 | 대응 |
| --- | --- |
| 기존 D3DX·도구 체인 의존성이 큼 | 새 렌더러는 도형과 최소 D3D11 기능으로 시작 |
| 기존 자료를 그대로 사용할 수 없음 | 직접 만든 도형·가상 시나리오로 모든 데모 구성 |
| UI·렌더 상태 동기화가 복잡함 | ID·명령 응답·소유 스레드 정책부터 고정 |
| 시간이 부족함 | 경로 재생·모델 import·테마 확장을 뒤로 이동 |
| 배포 환경마다 실패함 | 샘플과 런타임 의존성을 포함한 깨끗한 환경 검증을 우선 |
